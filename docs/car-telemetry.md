# 차량 데이터로 GPS 음영 보정 (2026-10-01 ~ 02)

터널이나 지하주차장에서 GPS가 끊겼을 때 차가 직접 보내는 속도·방위·위치로 화면의 차를 잇는 작업.
설치 절차는 [fleet/README.md](../fleet/README.md), 진행 상황 요약은 [STATUS.md](STATUS.md)에 있다.

## 왜

실차에서 터널을 지날 때 차가 튀었다. 원인은 기존 추측 항법이었다.

- GPS가 끊기면 **터널에 들어갈 때의 속도**로 경로를 따라 계속 밀었다. 안이 막혀도 마찬가지였다.
- GPS가 돌아왔을 때 화면 위치와 실제 위치가 40 m 넘게 차이 나면 **한 번에 순간이동**했다
  (주석에는 "1.5초에 걸쳐 복귀"라고 적혀 있었지만, 경로 안내 중에는 그 처리가 실제로 쓰이지 않았다).

모의 주행 "터널 정체"(60초 터널, 안에서 멈췄다 기어감)로 잰 결과:

| | 화면 위치와 실제 위치 차이 | 터널을 나올 때 |
|---|---|---|
| 기존 | 계속 벌어져 최대 707 m | 657 m를 한 번에 되돌아감 |
| 차량 속도 사용 | 내내 0~7 m | 거의 그대로 |

## 구조

```
차 ──(Owner 스트리밍: 서버가 Tesla에 접속)──┐
차 ──(Fleet Telemetry: 차가 우리 서버에 mTLS 접속 → Redis)──┤
                                              ▼
                         server/src/car/  (hub: VIN별 구독, 열린 페이지가 있을 때만)
                                              │  SSE  /api/car/stream
                                              ▼
            web/src/car-link.ts → car-track.ts → tracker.ts (추측 항법)
```

| 파일 | 하는 일 |
|---|---|
| `server/src/car/owner.ts` | Owner API 로그인(PKCE), 토큰 갱신, 차 목록, 스트리밍 클라이언트 |
| `server/src/car/fleet.ts` | Fleet API 로그인·파트너 등록·텔레메트리 설정, 텔레메트리 레코드 해석, Redis 구독 |
| `server/src/car/schnorr.ts` | Tesla.SS256 서명(P-256 Schnorr). vehicle-command 테스트 벡터와 바이트 단위로 일치 → Tesla 프록시 불필요 |
| `server/src/car/redis.ts` | PSUBSCRIBE 하나만 하는 최소 Redis 클라이언트 |
| `server/src/car/hub.ts` | VIN별 청취자와 스트림 하나. 마지막 페이지가 닫히고 1분 뒤 Tesla 연결을 닫음 |
| `server/src/car/index.ts` | `/api/car/stream`(SSE), 공개키, `/admin/car/*` |
| `web/src/car-track.ts` | 샘플을 차 시각 기준으로 쌓고 "t1~t2 사이 간 거리"(`between`), 경로 밖 이동(`freePath`) 계산 |
| `web/src/car-link.ts` | EventSource 연결과 해제, 샘플 간격 집계 |
| `fleet/` | fleet-telemetry 설정, 인증서 배치 스크립트, 설치 절차 |

## 추측 항법 동작

**경로 안내 중 (경로 위)**
- 마지막 GPS 시점부터 차가 실제로 간 거리만큼 경로를 따라 민다. 샘플 사이는 직전 속도를 유지한 것으로 보고 적분한다(텔레메트리는 값이 바뀔 때만 오므로).
  오도미터가 10 m보다 촘촘하면 오도미터를 쓴다.
- 샘플이 늦게 오거나 순서가 뒤바뀌어 와도 다음 계산에서 저절로 맞춰진다.
- LTE까지 끊기면 차가 마지막으로 알려 준 속도로 이어 간다.
- 차 데이터가 있으면 느리게 들어간 경우(3 m/s 미만)에도 추정하고, 최대 30분까지 이어 간다(없으면 10분).
- 차 데이터가 없으면 예전처럼 마지막 GPS 속도로 밀되, 경로가 정체 구간이라고 하면 속도 상한을 둔다.

**경로 밖 (경로 없음, 또는 이탈 중)**
- 차 자체 추정 위치가 차의 이동에 맞춰 움직이면 → 그 변화량으로 옮긴다.
- 추정 위치는 멈췄지만 방위가 3° 넘게 바뀌면 → 방위 + 속도로 계산한다.
- 둘 다 멈춰 있으면 → 그 자리에 둔다. GPS와 함께 멈춘 방위로 직진시키면 벽을 뚫고 나가기 때문이다.

**공통**
- 흐린 GPS(정확도 40 m보다 나쁨)가 들어와도 차가 움직이고 있다고 하면(최근 10초 안 1.5 m/s 초과) 그 GPS로 차를 붙잡지 않는다.
- GPS가 돌아오면 1.5초에 걸쳐 미끄러지듯 복귀한다. 거리가 멀어도 순간이동하지 않는다.
- 터널 안에서는 큰 속도 표시도 차량 속도로 바뀐다.

**스트리밍을 켜는 때**: 경로 안내 중에는 항상. 경로가 없을 때는 GPS가 3초 넘게 안 오거나 정확도가 40 m보다 나빠지면 켜고, 1분간 좋으면 끈다.
차가 연결되지 않은 계정은 서버가 204를 돌려주고, 브라우저는 10분 동안 다시 묻지 않는다.

## 두 가지 받는 길

| | Owner 스트리밍 (사용 중) | Fleet Telemetry (준비만 됨) |
|---|---|---|
| 공식 여부 | 비공식 (TeslaMate 방식) | 공식 |
| 준비 | Tesla 로그인 | 앱 등록, 파트너 등록, 키 페어링, 포트 포워딩, 인증서 |
| 속도 | 1 mph 정수 | `VehicleSpeed` |
| 오도미터 | **0.1마일(161 m) 단위** → 거리 계산에 안 씀 | `Odometer` (정밀도는 받아 봐야 앎) |
| 위치·방위 | `est_lat/est_lng`, `est_heading` | `Location`, `GpsHeading` (5초) |
| 고도 | `elevation` (받기만 함) | 없음 |
| 주기 | 주차 중 약 3초. 주행 중은 측정 예정 | 값이 바뀔 때, 최소 1초 |
| 비용 | 없음 | 신호 15만 개당 $1. 계정마다 매달 $10 할인(주행 약 200시간). 결제 수단이 없으면 한도 $0이라 과금 대신 차단 |

### Owner 스트리밍에서 겪은 함정 (2026년 기준)

1. **로그인 복귀 주소**: `https://auth.tesla.com/void/callback`은 2026년 4월에 없어졌다.
   `ownerapi`에 등록된 주소는 `tesla://auth/callback` 하나다. 브라우저는 이 주소를 열지 못하므로,
   로그인 뒤 개발자 도구 Console에 뜨는 `Failed to launch 'tesla://auth/callback?code=…'` 줄을 복사해 붙여 넣는다.
2. **토큰 요청은 HTTP/2 + TLS 1.3**: HTTP/1.1(Node `fetch`)로 토큰을 받으면 Tesla가 Fleet 전용 토큰을 주고,
   Owner API가 `403 forbidden, see fleet-api`로 거절한다(TeslaMate #5384, 2026년 6월). `node:http2`로 보낸다.
3. **차 목록은 `/api/1/products`**: `/api/1/vehicles`는 이제 Fleet API에서만 된다(412).

이 세 가지를 고친 뒤 실제 차 1대를 받았고, 스트리밍으로 20초 동안 샘플 8개를 받았다.

### Fleet 쪽 준비 상태

- 공개키: `https://<도메인>/.well-known/appspecific/com.tesla.3p.public-key.pem`
  (키 파일 `/mnt/data/webnavi/config/tesla/fleet-key.pem` — **지우면 파트너 등록과 페어링부터 다시**)
- 앱 리디렉션 URI: `https://<도메인>/admin/car/tesla/callback`
- 텔레메트리 서버: `telemetry.<도메인>:8443`. Cloudflare DNS only, 공유기 8443 → 이 서버 8443,
  `docker compose --profile fleet` (fleet-telemetry v0.9.5 + Redis)
- 인증서: Let's Encrypt RSA, **2026-12-30 만료, 자동 갱신 없음**. 체인은 YR1 → Root YR(교차 서명) → ISRG Root X1
- `/admin`의 ①~④(파트너 등록, 로그인, 키 페어링, 설정 보내기)는 아직 안 누름. ④를 보내야 차가 데이터를 보내기 시작하고 비용이 쌓인다.

## 확인 방법

차 화면 진단 로그(서버 `/mnt/data/webnavi/client-logs/`):
- `차량 스트리밍: streaming` — 받는 중
- `차량 첫 샘플: 속도 … · 오도미터 160.9 m 단위 · 차 자체 위치 있음`
- `차량 샘플 N개 · 간격 중앙값 N ms · 최대 N ms` — 1분마다, 실제 주기
- `추측 항법 끝 42초 · 차량 속도 · GPS와 +6 m · 차 자체 위치와 GPS 15 m` — 터널을 나올 때의 오차
- `추측 항법 끝 … 경로 밖 · 차량 방위·위치 · GPS와 N m 떨어짐`

책상에서는 모의 주행의 **터널 정체** 버튼.

## 아직 모르는 것

- 주행 중 Owner 스트리밍의 실제 간격. 2~3초면 Fleet(1초)로 바꾸는 것을 권함
- 차 자체 추정 위치·방위가 터널 안에서도 살아 있는지(위 로그의 "차 자체 위치와 GPS" 값)
- Fleet 오도미터 정밀도
- Owner 스트리밍이 언제까지 될지 (비공식)

## 같은 기간의 다른 수정

- **상단 가운데 겹침**: 차선 안내 카드, 분기점 확대 표시, 구간단속 표시를 실제 높이로 위에서부터 쌓는다(`main.ts` `measure`).
  예전에는 구간단속을 고정 96 px 아래에 두어, 긴 차선 카드(180 px 이상)와 겹쳤다.
- **모의 주행에서 속도를 올려도 화면이 빨라지지 않는 것처럼 보이는 문제**: 버그가 아니다. 차 이동은 즉시 빨라지지만,
  자동 줌이 4초쯤에 걸쳐 줌아웃해서(60→180 km/h에서 17.8→16.2) 화면상 움직임은 비슷하게 보인다.
  필요하면 자동 줌을 약하게 하거나 더 빨리 바뀌게 할 수 있다.
